# 0015 双栏对比页与单文件跨设备读写

- 状态:已实现
- 日期:2026-09-18
- 相关:[0013 目录内容对比](./0013-folder-content-diff.md)、[0014 中转](./0014-relay.md)

## 背景

0013 给出的对比是**差异清单**:一份「哪些文件不一样、属于哪一类」的报告。它回答
「同步是不是出了问题」,但回答不了紧接着的那个问题 —— **那到底差在哪一行**。
用户排查到「a.txt 两边不一致」之后,还得自己去两台机器上打开文件比对。

同时 0013 立下了一条原则:诊断工具**全程只读**,绝不扰动被观察的系统。这条原则
在「看目录差异」时完全正确,但它把「看完顺手修一下」这条路也堵死了。

本 ADR 记录两件事:
1. 新增 `/compare/<folderId>` 双栏对比页(两侧目录结构逐行对齐 + 文件内容对比);
2. 为它新增的**单文件跨设备读写**通道 —— 这是 0013 只读原则的**唯一例外**,以及
   为了让这个例外不把数据搞坏而立的规则。

## 决策

### 1. 双栏对比:目录结构是主视图,差异清单退居其次

路径路由 `/compare/<folderId>`,设备走 `?device=` 查询参数(可缺省,页面上选)。
目录 id 不存在时页面直接渲染错误页,而不是一个空表格。

数据来自新增的 `GET /api/folders/compare`,它返回**差异分类 + 两侧完整条目清单**。
0013 的 `/api/folders/diff` 刻意不返回 in-sync 的条目(报告里它们没有信息量),
但目录结构视图必须看到「两边都一样的那些文件」—— 否则用户无法相信「对齐」是
完整的,看到一个有大量缺口的树只会以为同步坏了。

对齐规则:**同一相对路径只占一行**,缺失的一侧留空行占位。目录同样成行,并且
「目录内有差异」要标记出来 —— 目录可以折叠,折叠时目录名本身必须能提示
「这里面有东西不一样」。

### 2. 单文件读写:两条新的控制消息

- `file-content-request` / `file-content-response`:向对端索取单个文件内容。
- `file-content-write` / `file-content-write-result`:请对端按给定内容落盘并
  **采纳给定版本**。

两者都复用 `serveIndexSnapshot` 那道共享关系闸门:**目录没把对方列进 `devices`
就一个字节都不给、一个字节都不写**。否则这条通道会变成绕过共享关系的任意文件
读取/写入入口。落盘路径一律经 `resolveSharePath`,硬忽略与符号链接越界的防护
与同步链路完全一致。

体积上限 2 MiB:内容以 base64 经控制通道回传,再进 JSON 给浏览器做行级差异,
再大既撑帧也不可读。超限弹窗降级为「整文件覆盖」,不回传内容。

### 3. 同步后的版本怎么给(本 ADR 最需要小心的地方)

写入有两侧,每侧都记着一个版本向量。关键是**写入之后两侧版本设成什么**:

- **写入后两侧内容完全一致** → 两侧都置为 `mergeVersions(本地, 对端)`。
  两端立刻判 `equal`,不再互推,一次点击就收敛。
- **只应用了部分差异块(两侧仍不同)** → 目标侧置为 merge 后,再自增**目标设备**
  自己的计数器,即把它当作**目标侧的一次真实编辑**,由正常同步传播过去收敛。

第二种情况**绝不能**把两侧版本设成相等。那正是 0013 里最强的异常信号
「版本相同但内容不同」:两端都以为一致,这份差异会永远沉下去,再也不会被任何
一轮同步或任何一份对比报告发现。宁可多一次传播,也不能制造这种状态。

`direction` 语义:`pull` = 写入本机(用对端内容或前端给定内容);`push` =
写入对端。`content` 省略表示「整文件照抄来源侧」,给了则以给定内容为准
(逐块应用的结果)。

### 4. 被写的一侧不自增计数器

`file-content-write` 让接收方**采纳**发送方给定的版本,而不是让它自增自己的
计数器再等下一轮扫描发现。自增会把这次写入判成「本机新编辑」再推回来,一次点击
变成两轮无意义传输。

## 影响

- 0013 的「全程只读」原则收窄为:**目录级对比只读;单文件内容对比与同步是唯一
  例外,且需要用户在弹窗里显式触发**(不存在任何自动写入路径)。
- 单文件同步会写 `update` 类型的同步记录,历史里能看到「谁在什么时候把哪个文件
  同步到了哪一侧」。
- 前端新增 `web/utils/route.ts`(极简路由)、`web/ComparePage.vue`、
  `web/components/FileDiffModal.vue`、`web/utils/tree.ts`(对齐)、
  `web/utils/text-diff.ts`(行级差异)。行级差异与对齐都是纯函数,有单测覆盖。

## 未做

- 目录级批量同步(把整个目录按差异批量推/拉):会显著放大误操作面,暂不提供。
- 三方合并视图:两侧之上再引入「原始版本」做三向合并。当前只做双向。
- 二进制文件的逐块对比:超限/二进制一律降级为整文件覆盖。
